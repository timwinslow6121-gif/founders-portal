# UHC PARTD $4.59 Renewal — Split at Agent Rate (not 100% Founders override)

## Why this exists

UHC's accounting forces reverse-engineering. The portal classifies a **$4.59** UHC renewal as a
100% Founders override (no agent split). That is correct for the MA families, but **WRONG for
Part D**: a $4.59 on a **PARTD** plan is a real renewal that splits to the agent at their
contract rate. AJ has to hand-fix these.

**The rule (Tim, 2026-06-26):** cross-reference **column M / Plan Type** (`_UHC_PLANTYPE`, col 12)
before deciding what a $4.59 is:
- Plan type ∈ {**MAPD, DSNP, CSNP, MA**} → $4.59 is **100% Founders override** (unchanged).
- Plan type == **PARTD** → $4.59 is a **renewal that SPLITS at the agent's UHC contract rate**.

## Grounding case (live data, member Dianne R. Pinkston)

Two independent line items, handled differently:

| source_ref | amount | plan | what it is | correct treatment | current state |
|---|---|---|---|---|---|
| `uhc::0::501` (row 502) | $0.26 | PARTD | the fixed PARTD **override** fee | 100% Founders override — **unchanged** | ✅ `founders_override` (correct) |
| `uhc::0::258` (row 2244) | $4.59 | PARTD | a PARTD **renewal** | **split at agent's rate** | ❌ `founders_override` (WRONG — this is the bug) |

For a 55% agent (Tim / Justin / Chris): $4.59 × 0.55 = **$2.5245 to the agent**, **$2.0655 to
Founders** (Founders' normal keep on the split — NOT a separate override row). For Mike (0.525):
$2.41 / $2.18. Brian/Anjana (0.50): $2.295 / $2.295. **The rate MUST come from the agent's UHC
contract (`agent_carrier_contracts` = the Agent Settings module = source of truth), never a
hardcoded 55%.** (Confirmed live rates: Chris/Justin/Tim/Rebekah 0.55, Mike 0.525, Anjana/Brian
0.50, Betty 0.0.)

## Root cause (confirmed in `app/commission/ledger.py`)

`_UHC_OVERRIDE_FAMILY` (ledger.py:604) = `{"MAPD","DSNP","CSNP","MA","PARTD"}` — it INCLUDES
PARTD. The renewal override branch (ledger.py:822-826):

```python
# ── MA / Part D renewals: override-aware (the $4.59 / combined logic).
if is_renewal and in_override_family:        # in_override_family is True for PARTD
    if _near(amount, _UHC_OVERRIDE):         # _UHC_OVERRIDE = 4.59, no plan-type check
        out.append(draft(_UHC_OVERRIDE, FOUNDERS_OVERRIDE, None, sref))   # 100% Founders — WRONG for PARTD
        continue
```

So a PARTD $4.59 renewal matches `_near(amount, 4.59)` and is emitted as 100% `FOUNDERS_OVERRIDE`
with no agent split. There is no plan-type carve-out for the PARTD case here.

## The fix

Add a guard **before** the $4.59 override branch (i.e. after the existing $0.26 PARTD-override
branch at ledger.py:810-813, before the `if is_renewal and in_override_family:` block at 823) so a
PARTD $4.59 renewal routes to the **plain agent-commission renewal** path instead of the override
path:

```python
# ── PARTD $4.59 renewal SPLITS at the agent's rate (it is NOT a Founders override
#    like the MA-family $4.59). Plan type (col M) is the discriminator. The $0.26
#    PARTD override is handled above and is unaffected.
if is_renewal and plan == "PARTD" and _near(abs(amount), _UHC_OVERRIDE):
    cls = CHARGEBACK if amount < 0 else AGENT_COMMISSION
    out.append(draft(amount, cls, rate, sref))   # rate = agent's UHC contract rate via split_lookup
    continue
```

This is ONE renewal line, `raw_amount = $4.59`, `split_rate = rate` (the agent's contract rate
the loop already resolved via `split_lookup` for this row). `split_breakdown()` then derives the
agent payout and Founders keep automatically — exactly how every other renewal is stored. NO
separate override row is created for the $4.59 (the $2.0655 is Founders' normal split share, not
an override). A negative $4.59 PARTD (chargeback) is handled symmetrically.

**What stays unchanged:**
- $4.59 on MAPD/DSNP/CSNP/MA → still 100% `FOUNDERS_OVERRIDE` (the existing branch at 824).
- $0.26 PARTD → still 100% `FOUNDERS_OVERRIDE` (the branch at 810).
- The combined-line ($33.51/$30.68) decomposition and all other renewal logic.
